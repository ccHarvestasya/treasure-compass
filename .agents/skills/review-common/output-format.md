# レビュー成果物の形式

レビュー成果物は Markdown とし、対象 Review Skill が別途指定しない限り次の共通構成・章名・順序を使用する。該当しない項目は「なし」と記載する。判定値、重大度、指摘 ID などの識別子は、対象 Review Skill の規則を使用する。

1. レビュー対象: 対象、確認日、範囲、未確認範囲
2. 使用した根拠: 確認資料と用途
3. レビュー結果: 対象 Skill の判定
4. 総評: 総評
5. 指摘事項: ID、重大度、対象箇所、事実、根拠、影響、最小修正、再確認条件
6. 解消済み指摘: 過去指摘の対応確認
7. 上流へのフィードバック: 上流資料の不足・曖昧さ・矛盾
8. 保留した指摘: 下流、対象外、後続検証への引継ぎ
9. 対象範囲と追跡: 対象境界と根拠の追跡
10. 検証結果: 実行結果、未実行、未確認範囲
11. レビューゲート: ゲートごとの判定と根拠
12. 残存リスクと未決定事項: 残存リスク、未決定事項、前提
13. 自動変更: レビュー中の変更。なければ「なし」
14. 最終判定: レビュー結果と同じ最終判定

## 指摘の分類

- **指摘事項**: 現在レビューしている工程自身の正式 Finding。対象 Skill の重大度・ID・Gate 規則に従う。
- **上流へのフィードバック**: 現在工程では解決すべきでない、上流成果物の不足・曖昧さ・矛盾。
- **保留した指摘**: 下流工程、後続検証、対象外、または現在評価できない事項。対象 Skill が別に定める場合はその分類を優先する。
- **自動変更**: Reviewer は原則レビュー対象を変更しないため、通常は「なし」。明示された修正ワークフローがある場合だけ事実を記録する。

## 追跡と境界

対象工程の成果物と、必要な上流根拠・関連資料を追跡できるようにする。下流成果物への追跡は、引継ぎ可能性や明白な矛盾の確認に限り補助的に行い、下流の存在だけで新しい上流要求や Finding を作らない。

## レビューの独立性

レビュー本文に思考過程、credential、secret、token、password、個人情報、機密データ、環境変数の値、入力の生データを記録しない。レビュー中は対象成果物、上流成果物、下流成果物、コード、テスト、README、設定を変更しない。
