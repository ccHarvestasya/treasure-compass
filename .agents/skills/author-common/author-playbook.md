# Author Playbook

作成系 Skill 共通の規則。

## 前提

- 対象は React / TypeScript / Vite の Treasure Compass。実装は src/、テストは tests/、静的データと画像は public/ にある。
- ルート AGENTS.md は作業方法の根拠であり、アプリ仕様の正本ではない。
- docs/concept/、docs/requirements/、docs/design/、docs/specifications/ は、実在し対象に必要な場合だけ参照する。
- README.md、package.json、型、定数、実装、テスト、静的データを、依頼に必要な範囲で確認する。

## Phase Context

Phase Context は正式資料の探索を助ける非規範的な派生情報である。AGENTS.md に対象フェーズの登録がある場合だけ初期探索に使う。登録のない Context を探索しない。

Context と正式資料が競合した場合は正式資料を優先する。Context にない事項、鮮度が不明な事項、外部契約・責務・データ形状・エラーに関する判断は、正式資料またはユーザー依頼へ戻る。

## 根拠と境界

根拠は、ユーザー依頼、承認済み上流文書、同一フェーズの成果物、README と既存契約、実装・テスト・データ、依存ライブラリの公式資料の順で必要な範囲を確認する。下流資料から新しい上流要求を作らない。

入力にない機能、画面、設定、保存項目、制約、数値、エラー、将来構想を追加しない。方式が未決定なら推測で規範化せず、未決定事項または下流への引継ぎに置く。成果物は依頼された文書種別だけに限定する。

## 作成手順

1. 対象、出力先、更新可否、依頼された範囲を確定する。
2. 上流資料、同一フェーズの成果物、対象コード・テスト・データを必要な範囲で確認する。
3. 情報を事実、要求、制約、仮定、未決定事項、将来構想へ分類する。
4. 対象文書の抽象度に合う内容だけを採用し、根拠へ追跡できるようにする。
5. 本文、図表、用語、リンク、ファイル参照の整合性を確認する。
6. 指定された成果物だけを作成・更新し、差分と状態を確認する。

## 完了

変更ファイルを確定してから AGENTS.md の change-aware validation を適用する。文書・Skill の変更だけならアプリの lint / test / build を実行しない。未実行の検証を成功として記録しない。ユーザーが依頼しない限り commit、push、tag、publish は行わない。
