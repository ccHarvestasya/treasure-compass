# Design Author

承認済み要件を、実装者が責務と依存方向を共有できる基本設計へ整理する。設計はコンポーネント・状態・データの責務を定めるが、不要な API やコード詳細を固定しない。

## 参照

1. AGENTS.md
2. ../author-common/author-playbook.md
3. Context の登録がある場合だけ対象 Context
4. 依頼、承認済み要件、既存の設計・設計判断
5. 必要な場合だけ README、実装、テスト、データを実現可能性・回帰確認のために参照する

## 設計対象

必要な範囲で次を整理する。

- React の画面責務とコンポーネント境界
- Zustand が所有する状態、派生状態、更新責任、localStorage との境界
- マップ JSON と画像の読み込み、検証、表示までのデータフロー
- 入力解析、座標検索、経路計算、マクロ生成などの純粋処理の責務
- UI、ストア、純粋関数、ブラウザ API、静的資産の依存方向
- ローディング、キャンセル、解析不能、破損データ、再計算、リセットの失敗境界
- 変更後に確認すべきテスト、fixture、ブラウザ上の確認
- データ所有、保存期間、更新・置換、外部通信の前提

## 決めない内容

要件にない機能、公開 API、画面の細部、JSON field、保存キー、error code、ライブラリ変更、具体的なアルゴリズム・閾値、CSS、React の function/module、テストケースを設計だけで発明しない。仕様で一意化が必要な事項は未決定事項または仕様への引継ぎにする。

既存アプリの実体と設計が異なる場合、互換性要求を推測せず、差分と影響を記録する。

## 標準構成

1. 目的と適用範囲
2. システムコンテキストと責任境界
3. コンポーネントと責務
4. データフローと状態所有
5. 依存方向と入力境界
6. 主要フローと失敗境界
7. 保存・資産・運用前提
8. 検証方針
9. 設計判断と未決定事項
10. 要件 Traceability

設計判断を記録する場合は、選択肢、採用理由、影響、未解決点を明記する。
