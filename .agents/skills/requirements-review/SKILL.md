# Requirements Review

要件が目的と利用者に対応し、設計・仕様へ安全に引き渡せる品質かを判定する。要件、コード、READMEを直接修正しない。

## 参照

1. AGENTS.md
2. ../review-common/review-playbook.md
3. ユーザー指定の要件、対応するコンセプト
4. 同じディレクトリの reviewers、review-gates、output-format、security-checklist が存在する場合
5. 必要な範囲の README、既存設計、仕様、実装、テスト

下流資料は回帰・互換性・実現可能性の確認に限り補助的に使い、下流の不足を要件の欠陥へ変換しない。

## 観点

- 各要件が目的、利用者、利用場面、責任へ追跡できるか
- 対象、対象外、責任境界、外部依存が明確か
- 機能要件と非機能要件が利用者に観測・検証できるか
- 入力、マップデータ、保存データ、エラー、失敗時安全性の責任が抜けていないか
- UI、ブラウザ、アクセシビリティ、性能、互換性、ライセンスの要求が必要な場合に明確か
- API、field、JSON schema、保存キー、内部状態、ライブラリ、テスト方式を先取りしていないか
- 未決定事項と受け入れ条件が、後続工程の推測を減らしているか

チェックリストだけで新しい要件やセキュリティ方針を発明しない。ユーザー入力を扱う要求がある場合だけ、表示安全性、保存の範囲、異常入力、外部送信の有無を要件レベルで確認する。

## 判定

判定は READY または REVISE REQUIREMENTS とする。Critical が1件以上ある場合だけ後者とする。Critical は、目的・責任・外部契約・安全性を一意に確定できず、下流で安全に補完できない欠陥に限る。Major / Minor は次工程への確認事項として整理できる場合がある。

成果物は ../review-common/output-format.md の構成に従い、要求ID、根拠、影響、修正条件、未確認範囲を追跡可能にする。
