# Implementation Author

承認済みの仕様と設計を、最小十分なコード・データ・テストの変更へ反映する。依頼されていない新機能や、実装上の都合による外部挙動を追加しない。

## 参照順序

1. AGENTS.md
2. 対応する上流要件、設計、仕様、既存レビュー
3. README.md、package.json、tsconfig、Vite / ESLint 設定
4. 変更対象の src、tests、public/json、public/img
5. 必要な場合だけ依存ライブラリの公式資料

対象仕様がなく、外部可視動作を決める必要がある場合は、推測で実装せず未決定事項として報告する。

## 実装境界

- React コンポーネントは表示とイベントの責務を保ち、計算・解析は既存の純粋関数境界を尊重する。
- Zustand の状態、派生状態、リセット、再計算、永続化対象を勝手に拡張しない。
- JSON の読み込みでは参照先、キャンセル、ロード失敗、想定外データを安全に扱う。
- チャット入力、名前、座標、マップ名を未検証のまま HTML やコードとして実行しない。
- 座標単位、距離、テレポートコスト、順序、丸め、マクロ文字列を根拠なく変更しない。
- GRADE_CONFIG、静的 JSON、画像ファイル名の対応を保つ。生成物や編集用資産の正本を取り違えない。
- UI の外部挙動を変えたら、境界・失敗系・回帰をテストへ反映する。

## 実装手順

1. 対象変更、既存差分、上流契約、影響ファイルを確定する。
2. 既存の型、状態、入力、データ形状、テストを読む。
3. 必要最小限のコードまたは静的データを変更する。
4. 外部挙動の変更に対応するテストを追加・更新する。
5. lint、test、build を変更分類に応じて実行する。
6. 差分、ログ、生成物、未検証範囲を確認する。

## 失敗と安全性

空入力、解析不能行、未知マップ、境界座標、空メンバー、重複、最大人数、複数マップ、ロード失敗、キャンセル、破損 localStorage、グレード変更、リセット、再計算を対象に、該当するものを確認する。エラーやログにチャット本文、ユーザー名、保存データを不要に含めない。

## 自己確認

- 変更が要件・設計・仕様または依頼へ追跡できる。
- 型、UI、状態、静的データ、保存、エラーの責務を越えていない。
- 仕様にない入力変換、fallback、公開 API、依存を追加していない。
- 既存のファイル名、保存キー、マクロ、座標、経路の意味を確認した。
- 関連テストと lint / build の結果を正確に報告できる。

レビューが必要なら implement-review を使う。この Skill 自身はレビュー成果物を作らない。
