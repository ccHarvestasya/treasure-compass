# Project Dialogue

この Skill は、ユーザーとの対話を通じてプロジェクト固有の判断を整理し、
今後のセッションでも必要となる情報を `MEMORY.md` に保持するためのものである。

## 基本方針

ユーザーの考えを推測して確定事項にしてはならない。

不明点、選択肢、矛盾、トレードオフを整理し、
必要な判断をユーザーとの会話によって決定すること。

一度に大量の質問をしてはならない。
現在の判断に最も影響する論点から、原則として1つずつ確認すること。

## MEMORY.md

作業開始時に `MEMORY.md` が存在する場合は参照すること。

`MEMORY.md` には、このプロジェクト固有かつ将来のセッションでも
必要となる情報だけを保存する。

保存対象:

- ユーザーが明示的に決定した事項
- 会話の中で合意された方針
- 継続的に有効な制約
- 重要な設計判断
- 現在未解決で、次回以降も検討が必要な事項
- 過去の判断を理解するために必要な背景

保存しないもの:

- 一時的な思考過程
- Codex自身の推測
- 採用されなかった案
- 一時的なデバッグ情報
- 詳細な作業ログ
- Git履歴から容易に取得できる情報
- 正式文書の全文コピー

## 決定の扱い

情報を次の状態として扱う。

### Confirmed

ユーザーが明示的に決定または承認した事項。

`MEMORY.md` に保存してよい。

### Tentative

方向性は示されているが、まだ確定していない事項。

原則として確定事項として保存しない。
必要であれば Open Context として未決定であることを明示して保存する。

### Open

まだ判断されていない事項。

必要ならユーザーに質問する。

### Rejected

検討されたが採用されなかった事項。

通常は保存しない。
ただし、将来同じ議論を繰り返す可能性が高く、
却下理由自体が重要な場合のみ Historical Context に残してよい。

## 対話

質問は、現在のプロジェクト判断を前進させるために必要なものだけにする。

質問する前に、既存の `MEMORY.md`、`AGENTS.md`、
および関連する正式文書から既に回答済みでないか確認すること。

ユーザーが曖昧な回答をした場合は、
勝手に詳細化せず、必要な部分のみ追加確認する。

選択肢が存在する場合は、

- 選択肢
- 主な利点
- 主な欠点
- 既存方針との整合性

を簡潔に示してよい。

最終判断はユーザーに委ねる。

## 工程境界

`MEMORY.md` は Concept、Requirements、Specification、Design の
正式成果物の代替ではない。

正式文書が存在する事項については、その文書を正とする。

会話で正式化すべき事項が十分に固まった場合は、
対応する工程の Skill に引き継ぐことを提案してよい。

ただし、この Skill 自身が勝手に正式成果物へ昇格させてはならない。
