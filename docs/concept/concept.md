| 項目 | 内容 |
| --- | --- |

この文書は、Treasure Compass と Mob Compass について、「何を、誰のために、どこまで作るか」を定める。具体的な入力、画面、データ、経路計算、保存、公開構成および検証条件は要件定義以降で決める。

## 1. コンセプト概要

Treasure Compass と Mob Compass は、FFXIV 内の巡回対象を登録し、地図上の位置と巡回順を確認しながら進行を管理するブラウザアプリである。別マップへの移動にはテレポによるゲーム内通貨やロード時間の負担があり、同じマップ内でも複数地点を探す負担があるため、対象に応じた巡回地点について、移動と探索の負担が最小となる巡回経路を算出する。

Treasure Compass は、パーティーメンバーごとに現在の宝箱地点を登録し、トレジャーハントの巡回を支援する既存アプリである。Mob Compass は新しい別アプリとして、モブハント固有の登録と探索を支援する。両アプリは別 URL の独立した公開単位とし、入力、周回状態および保存を混在させない。一方で、地図表示、地点選択、経路表示、進行管理という基本的な利用感は共有する。

Mob Compass には、用途が異なる「ソロ」と「パーティ」がある。ソロはデイリー・ウィークリー手配書の一般モブから B モブまでを個人で巡る用途、パーティはゲーム内チャットで共有された A モブ以上の出現情報をリーダーが手動登録して巡る用途である。両者は別の周回として扱い、登録対象や進捗を混在させない。

## 2. 解決する課題 / 対象ユーザー

### 解決する課題

- Treasure Compass の利用者が、複数メンバーの宝箱地点と巡回順、完了状況を把握する負担を減らす。
- 手配書に指定された一般モブや B モブについて、候補地点を確認し、複数マップと同一マップ内を効率よく巡る負担を減らす。
- A モブ以上の出現情報を受け取ったリーダーが、報告地点を整理し、パーティの巡回順と進捗を管理する負担を減らす。
- Treasure と Mob で共通する地図操作と巡回操作を揃え、利用者が別アプリでも同じ感覚で扱えるようにする。
- 新しいエリアや対象が追加された際に、巡回に必要な基礎情報を継続して整備できるようにする。

### 対象ユーザー

- パーティーメンバーの宝箱を巡回する Treasure Compass の利用者。
- デイリー・ウィークリー手配書の対象を個人で巡る Mob Compass の利用者。
- A モブ以上の共有情報をもとに巡回を管理するパーティリーダー。
- 地図、移動拠点、宝箱候補地点、モブおよび出現候補地点を整備する管理者。

パーティの参加者は Mob Compass の直接の利用者とはせず、ゲーム内チャット等でリーダーから案内を受ける関係者とする。

## 3. 提供価値 / 代表利用フロー

Treasure Compass の利用者は、メンバーと宝箱地点を登録し、移動負担が最小となる巡回順を確認して現地を回り、完了状況を管理する。

Mob Compass のソロ利用者は、手配書の対象を名前から選び、一般モブでは巡回全体の負担が最小となる一つの出現地点を、B モブでは全候補地点を巡る最短探索経路を確認して巡る。パーティ利用者は、共有された A モブ以上の情報を見ながら既知の候補地点を手動で登録し、登録地点を巡る最短経路に沿って進行を管理する。

両アプリは、対象に固有の登録方法を保ちながら、「登録する → 地図と巡回順を確認する → 現地を巡る → 完了と残りを管理する」という基本体験を共有する。利用者が手動で順序を調整した場合はその意図を尊重し、誤った完了や探索操作を訂正できるようにする。

## 4. v1 スコープ / 対象外

### v1 スコープ

- Treasure Compass と Mob Compass を、別 URL、別状態、別保存境界を持つ二つのブラウザアプリとして提供する。
- 両アプリで、地図上の地点、巡回順、現在の進行、完了状況を確認・管理できるようにする。
- Treasure Compass で、メンバーと宝箱地点をもとに、別マップへの移動負担が最小となる巡回を支援する。
- Mob Compass のソロで、一般モブから B モブまでを名前から登録し、一般モブの討伐地点と B モブの全候補地点について、巡回・探索の負担が最小となる経路を算出する。
- Mob Compass のパーティで、共有された A モブ以上の報告地点をリーダーが手動登録し、登録地点を巡る最短経路を算出する。
- 自動で算出した順序と利用者が調整した順序を扱い、進行と訂正を管理できるようにする。
- 両アプリをスマートフォンで利用できるようにし、縦向きを主対象としつつ横向きでも主要操作を可能にする。
- 巡回に必要な地図、移動拠点、対象および候補地点を管理者が整備できる状態を保つ。

### v1 対象外

- ゲーム内状態、出現、討伐、現在地の自動取得・自動判定。
- 不定形なゲーム内チャットの自動解析、Mob Compass 専用チャットマクロの要求、チャットからの一括登録。
- 参加者向けの閲覧モードや共有画面。
- 共有状態の同期、共同編集、リーダー間の自動引継ぎ。
- サーバー、認証、高度な権限管理、常設コミュニティや FC の管理。
- 長期的な周回履歴、統計分析、通知。

チャット解析は、利用者から具体的な要望が出て、利用者と入力形式を合意できた場合に改めて検討する。v1 の成立条件や将来提供の約束には含めない。

## 5. 責任境界・判断原則

- 両アプリは、利用者が入力・選択・完了した情報をもとに巡回を支援する。実際のゲーム状態が入力どおりかを保証しない。
- 対象の登録、報告地点の選択、順序の採用、完了や探索結果の記録、参加者への伝達は利用者が行う。
- Treasure と Mob は別アプリとして状態を分離し、片方の操作、保存または消去がもう片方へ影響しないようにする。
- Mob のソロとパーティも用途と対象ランクが異なる別の周回として扱い、一方の操作、保存または消去がもう一方へ影響しないようにする。
- Treasure と Mob の対象モデルや登録フローを無理に共通化しない。共有するのは、意味が同じ地図・地点選択・経路表示・進行操作に限る。
- 自動計算よりも、利用者が明示的に変更した巡回順を優先する。再び自動順序へ戻す場合は利用者の明示操作を必要とする。
- マスターデータと利用者の周回情報を混在させず、アプリはマスターに存在しない対象や地点を推測して登録しない。
- スマートフォンを含む対応画面で、中核となる登録、地図確認、巡回、進行、訂正を利用不能にしない。

## 6. 成功状態

- Treasure Compass の利用者が、既存のトレジャーハント支援を継続して利用しながら、移動負担が最小となる巡回順と進捗を意図どおり管理・復元できる。
- Mob Compass のソロ利用者が、手配書の一般モブと B モブを登録し、巡回・探索の負担が最小となる経路で、一般モブの討伐と B モブの全候補地点探索を一つの巡回として進められる。
- Mob Compass のパーティリーダーが、共有された A モブ以上の地点を手動登録し、登録地点を巡る最短経路と進捗を管理できる。
- Treasure、Mob のソロ、Mob のパーティが互いの状態を混在・消去せず、それぞれの続きを再開できる。
- PC とスマートフォンのどちらでも、地図と巡回状況を確認し、主要な進行操作を完了できる。
- 両アプリで共通する操作感を保ちながら、宝箱、一般モブ、B モブ、A モブ以上に必要な扱いの違いを維持できる。

## 7. 要件定義への引継ぎ

- Treasure、Mob のソロ、Mob のパーティで、利用者が登録できる対象と、登録時に選択・確認する情報をどう区別するか。
- 名前検索、拡張エリア、種別・ランクによる絞り込みと、既知の候補地点からの選択をどのような外部動作にするか。
- 一般モブの訪問地点、B モブの全候補地点探索、A モブ以上の報告地点を、巡回対象と進行単位としてどう扱うか。
- 最短経路の算出において、別マップへの移動負担と同一マップ内の探索距離をどの順序と条件で評価し、利用する移動拠点と巡回順をどう決めるか。
- 自動順序、手動順序、対象の追加・変更・削除、完了・取消、B モブの探索進行・取消によって、巡回順と現在地点をどう変化させるか。
- Treasure、Mob のソロ、Mob のパーティについて、何をどの期間保存し、再読み込み、モード切替、消去、既存保存データをどう扱うか。
- 二つのアプリを利用者が別の公開単位として識別し、片方の操作がもう片方へ影響しないことをどう保証するか。
- スマートフォンの縦向き・横向きを含め、主要操作を利用可能とする表示条件と検証条件をどう定めるか。
- 空、不正、不完全、未知の入力やマスターデータ、保存失敗、経路計算不能をどのように扱い、利用者へどう伝えるか。
- マスターデータを誰が作成・確認・更新・公開し、出典と画像利用条件をどう管理するか。
