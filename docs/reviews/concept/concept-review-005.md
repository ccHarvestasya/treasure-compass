## コンセプト評価

Treasure Compass と Mob Compass は、FFXIV 内の巡回対象について、移動と探索の負担が最小となる巡回経路と進行を管理する別々のブラウザアプリとして明確に理解できる。既存の Treasure Compass を継続し、新規の Mob Compass を追加しながら、意味が同じ地図・地点選択・経路表示・進行操作だけを共有する方針は一貫している。

Mob Compass は、一般モブから B モブまでを扱う個人向けの「ソロ」と、共有された A モブ以上をリーダーが手動登録する「パーティ」に分かれている。対象ユーザー、課題、代表利用フロー、v1、責任境界、成功状態でこの区分が保たれ、チャット解析・一括登録を v1 対象外とする判断とも矛盾しない。アプリ間・モード間の状態分離、利用者の手動順序を尊重する原則、誤操作の訂正、スマートフォン対応も、企画上の価値と境界に対応している。

最短化は、概要、代表利用フロー、v1、成功状態で中核方針として明示された。B モブは全候補地点を探索対象とし、一般モブは巡回全体の負担が最小となる一地点、パーティは登録された報告地点を巡る最短経路として、用途ごとの価値も区別されている。距離尺度、移動拠点の選択、評価順序などは要件定義への問いに留められ、最短化するかどうか自体を後工程へ先送りしていない。

## 判定理由

コンセプトの目的、対象ユーザー、課題、提供価値、代表利用フロー、v1、対象外、責任境界、成功状態は相互に整合している。Treasure と Mob の分離、Mob のソロとパーティの分離、チャット解析を扱わない境界、最短経路と手動順序の関係も、後工程が企画意図を誤解しない形で示されている。

残る論点は、入力・検索・地点選択、最短経路の評価条件、進行と取消、保存・消去、対応画面、異常時、マスターデータ管理などの具体的な外部動作または実現方式である。これらは Requirements または Design で扱うべき内容であり、未決定であることを Concept Finding とはしない。未解決の Critical、Major、Minor はなく、要件定義へ進めるため Gate を **READY** とする。
