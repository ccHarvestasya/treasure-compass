## コンセプト評価

Treasure Compass と Mob Compass は、FFXIV 内の巡回対象を登録し、別マップへの移動をなるべく抑えるため、マップ間の移動が最小になるルートを算出して進行を管理するブラウザツールとして理解できる。最小化対象を、同一マップ内の地点間距離ではなく「あるマップから別のマップへの移動」と定義し、その背景をテレポに伴うゲーム内通貨とロード時間の負担として説明しているため、目的、課題、提供価値の関係は明確である。

対象ユーザーは宝箱を巡回する利用者、モブを個人で巡回する利用者、共有周回のリーダー、基礎情報を整備する管理者に分けられ、課題と利用フローに対応している。参加者は直接利用者ではなく、リーダーからチャット案内を受ける関係者とする境界も維持されている。

提供価値、v1 スコープ、成功状態のすべてで、両プロダクトがマップ間の移動を最小にするルートを扱うことが一貫している。Treasure Compass のメンバーと座標の1対1、Mob Compass のモブと複数候補座標の1対多という違いを維持しながら、登録、ルート算出、進行管理を共通体験としている。v1 対象外、責任境界、共有周回の方針との矛盾も確認されない。

要件定義への引継ぎでは、マップ間移動の数え方、同数候補におけるゲーム内通貨・ロード時間・その他の移動負荷の評価、複数候補座標からの巡回先選択を問いとして残している。これは中核方針を再判断へ先送りするものではなく、外部挙動と評価条件を具体化する Requirements の論点である。経路計算アルゴリズムや内部方式は決定しておらず、Concept と Requirements / Design の工程境界も保たれている。
