## 4. 総評

対象文書は、Concept の対象ユーザー、Treasure Compass と Mob Compass の対応関係、共有周回の責任境界、チャット案内、マスターデータ、対象外を、Requirements の能力・制約・受け入れ条件へ広く追跡できている。正確な入力形式、保存方式、アルゴリズム、UI、テストを下流へ送っており、工程境界も概ね守られている。

今回の修正で、`REQ-F-006` は登録された現在の対象集合から算出し、第一軸を異なるマップへの遷移回数の最小化、同数時の補助評価をテレポ料金・ロード時間とする要求へ具体化された。`REQ-F-004` / `AC-004` は Mob Compass の候補集合、採用候補、確認済み候補、同率候補を識別可能にし、`REQ-D-007` / `AC-016` は無効・未確認情報を有効扱いせず誤ったルート・進行更新を防いでいる。これにより前回の Critical は解消され、Requirements は Specification へ進められる。

残る論点は、遷移回数が同じ候補のとき、テレポ料金とロード時間を「抑える」方向でどう比較するかである。これは中核の第一軸を再び未決定に戻すものではなく、正確な比較方法を下流へ渡すための Major 任意改善として記録する。

## 5. 指摘事項

### RR-003 — Major — New（任意改善）

- 対象箇所: `docs/requirements/requirements.md:93-95, 173-175, 214-225, 234-247`
- 事実: `REQ-F-006` / `AC-005` は、遷移回数が同じ候補を比較する際にテレポに伴うゲーム内通貨とロード時間を「補助的に評価」すると定めた。一方、料金を低くすることとロード時間を短くすることの方向、両者の優先関係、同一評価にならない場合の外部的な選択基準は 9.1 / 9.2 で未決定としている。`REQ-F-004` / `AC-004` の「最小評価が同率」は、最終的な同率なのか遷移回数だけの同率なのかも下流で解釈し得る。
- 根拠: Concept 1（`docs/concept/concept.md:13`）は、別マップへの移動に伴うゲーム内通貨とロード時間をなるべく抑える理由を明記している。今回の修正で第一軸は確定したため、ここで指摘するのは第一軸の未確定ではなく、同数時の補助評価を外部結果へ引き渡す明確さである。
- 影響: 同じ遷移回数の候補について、料金が高いがロードが短い順序と、料金が低いがロードが長い順序のどちらを採用しても、現状の `AC-005` / `AC-015` は「補助的に評価した」と説明できる余地がある。結果の差は利用者のゲーム内通貨と待ち時間に影響するが、Requirements だけから合否を一意に判定できない。
- 最小修正: 同数時に料金とロード時間を低減する方向で評価すること、および両者が競合した場合の優先関係または同等扱いを Requirements で少なくとも方向レベルで確定する。通貨の具体単位、ロード時間の観測条件、比較式、アルゴリズムは Specification / Design へ残せる。
- 再確認条件: `REQ-F-006`、`REQ-Q-002`、`AC-005`、`AC-015`、Mob候補の同率条件が、同数時の補助評価の方向と選択結果を一意に追跡できること。製品判断として「同数時は任意選択」とする場合は、補助評価を必須とする記述と整合するよう明示されていること。
