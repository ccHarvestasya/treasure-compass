## 1. 適用範囲と規範

### 1.1 適用範囲

本仕様は、Treasure Compass と Mob Compass の v1 における入力、表示、状態遷移、経路、保存、失敗時の外部挙動を定める。本文の「する」「しない」は必須の契約を表す。

Treasure Compass と Mob Compass は、利用者がそれぞれを別のアドレスから直接開ける独立したブラウザアプリとする。具体的な URL 文字列、配備先、ビルド入口、モノレポ内のパッケージ構成および共有コード構成は本仕様では定めない。[REQ-F-001]

両アプリは地図上の地点選択、巡回順の手動変更、完了と取消、確認付き全消去、現在地点と完了状態の示し方について同じ意味の操作結果を提供する。一方のアプリを開くために、もう一方のアプリ内で製品モードを切り替える操作は要求しない。[REQ-F-005]

### 1.2 対象外

次を v1 の外部機能として提供しない。

- Mob Compass におけるゲーム内チャットの解析、一括登録および専用チャットマクロ。
- 参加者向け閲覧画面、共有状態の同期、共同編集およびリーダー交代。
- サーバー、認証、アカウント、高度な権限管理および常設コミュニティ管理。
- ゲーム状態、モブの出現・討伐・現在地の自動取得または自動判定。
- 長期履歴、統計、通知および一般モブの必要討伐数・途中討伐数の管理。

パーティ参加者への案内は利用者がゲーム内チャット等で行い、アプリは自動投稿しない。[REQ-S-001][REQ-S-002][REQ-S-003][REQ-S-004]

## 2. 用語と状態

| 用語                 | 外部から観測できる意味                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 対象                 | Treasure では正規化されたメンバー名に対応する一つの現在の宝箱地点、Mob では一体の登録済みモブ                                                                                                          |
| Treasure 巡回リスト  | Treasure の登録済み対象そのもの。登録集合と別の対象集合を作らず、未完了経路と完了を同じリスト上に表示する                                                                                              |
| 候補地点             | マスター上で対象に対応付けられた、X/Y を持つ地点。候補であることだけでは発見・完了を意味しない                                                                                                         |
| 訪問地点             | 現在の未完了巡回経路に含まれる地点                                                                                                                                                                     |
| マップ別現在地点     | 自動経路の再計算開始地点となる、最後に完了または探索した地点。対象の選択や「再生」だけでは変更しない                                                                                                   |
| リスト選択           | 利用者がリスト上で選択している 0 件または 1 件の登録項目。リスト選択だけでは現在対象、地図・案内の前面表示、完了、順序またはマップ別現在地点を変更しない。現在対象とは別に存在し得る                   |
| 現在対象             | Treasure プレイヤーが地図・案内を前面に表示し、「次へ」の対象としている登録項目。完了済みでもなり得る。リスト選択およびマップ別現在地点とは別の情報                                                    |
| 自動順序             | アプリが本仕様の評価規則により計算した巡回順                                                                                                                                                           |
| 手動順序             | 利用者が並べ替えた巡回順。明示的な自動計算が成功するまで維持される                                                                                                                                     |
| 再生                 | リスト選択があればその対象、なければ先頭の未完了対象を現在対象にし、対応する地図・巡回案内を前面に表示する操作。再生中／一時停止中という保存状態を作らない                                             |
| 次へ                 | Treasure では未完了の現在対象を完了にし、巡回順で次の未完了対象へ現在対象を進める操作。現在対象がない、または完了済みの場合は状態を変更しない                                                          |
| 戻る                 | 直前の連続した「次へ」による完了を一件ずつ取り消し、操作前の現在対象へ戻す操作。一般的な履歴ではない                                                                                                   |
| 未探索               | B モブの候補地点をまだ「次の地点へ」で除外していない状態                                                                                                                                               |
| 探索済み             | B モブの候補地点を訪れ、利用者が「次の地点へ」を実行した状態                                                                                                                                           |
| 未発見               | B モブの全候補地点が探索済みだが、対象自体は完了していない状態                                                                                                                                         |
| 完了                 | 利用者が対象単位で完了を明示した状態                                                                                                                                                                   |
| 有効なエーテライト   | 対象マップとの参照が解決し、検証済みの `division=T` レコードであり、マップの有効範囲内の有限な X/Y と町名を持つエーテライト。legacy `division=R`、未検証、参照不能または対象範囲外のレコードは含まない |
| エーテライト案内表示 | 有効なエーテライトのアイコンと町名を地図上に重ねて示す、地点登録とは別の情報表示                                                                                                                       |

候補地点の識別、表示および距離評価には、正規のマップ識別と有限数の X/Y を用いる。Z は入力、地点識別、表示および経路評価に用いない。[REQ-R-002][REQ-A-001]

## 3. アプリ、モードおよび画面状態

### 3.1 状態境界

Treasure の周回状態、Mob のソロ状態、Mob のパーティ状態は互いに独立する。一つの境界に対する登録、並べ替え、進行、保存、復元または消去によって、他の二つの状態を変更しない。[REQ-F-002][REQ-F-003]

Mob Compass は画面上部に「ソロ」「パーティ」のモード切替を常時表示し、選択中のモードを視覚的に識別可能にする。切替時は切替先の保持済み状態を表示し、切替元の状態を変更しない。再訪時は最後に正常保存された選択モードを開く。[REQ-F-003][REQ-F-004]

正常な保存状態がまだない初回利用では「ソロ」と「自動順序」を選択し、登録対象のない初期状態を表示する。初回表示だけでソロまたはパーティへ対象を登録しない。[REQ-R-006]

### 3.2 登録と巡回の表示切替

Mob Compass の操作領域は「登録」「巡回経路」の二つに分ける。対象を登録または更新した後も「登録」に留まり、登録操作を連続して行える。「巡回経路」への切替は利用者の操作による。[REQ-M-008]

Treasure Compass は一つの巡回リストを主表示とする連続した登録・順序確認・地図案内・進行の表面を提供する。登録済み対象、未完了経路、完了表示および現在対象は同じリストとその表示投影で識別できる。一括入力と手動入力は、主表示から必要時に開く同格の登録入口とし、各入口で成功した登録または更新の後は同じ巡回リストへ戻り、追加・更新結果を直ちに反映する。[REQ-T-001][REQ-T-002][REQ-D-003]

Treasure Compass に、一括入力・手動入力・巡回経路を三つの独立したトップレベル体験として並べることを要求しない。登録入口を閉じた後に別の準備／実行 domain mode へ切り替えず、Treasure に再生中／一時停止中の domain 状態または保存状態を設けない。[REQ-T-002][REQ-T-007]

### 3.3 共通操作の意味

両アプリで、同じ意味の操作は次の結果に揃える。[REQ-F-005]

| 操作                       | 共通する結果                                                               |
| -------------------------- | -------------------------------------------------------------------------- |
| 地図上のマスター地点を選択 | 選択対象に対応する有効なマーカーだけを選べる。地図上の任意位置は登録しない |
| 巡回順をドラッグ等で移動   | 移動後の並びを手動順序にする                                               |
| 「経路自動計算」           | 計算と保存が成功した場合だけ自動順序に切り替える                           |
| 「完了」                   | 対象を完了表示にし、未完了経路から外す                                     |
| 完了済み対象の「取消」     | その対象を未完了へ戻す                                                     |
| 「全消去」                 | 対象範囲を示す確認後だけ、その範囲を初期化する                             |

エーテライト案内表示のアイコンおよび町名ラベルは「地図上のマスター地点を選択」の選択対象に含めない。地点選択表示で選択できるのは、各アプリが登録対象として扱う有効な地点マーカーだけである。

## 4. Treasure Compass

### 4.1 手動登録

Treasure は登録済み対象を最大 8 件まで保持する。手動登録は、空白を除いたメンバー名と、利用者が選択した一つの有効な宝箱候補地点の両方を必須とする。名前が空、地点が未選択、地点がマスター上で無効または解決不能の場合は登録を拒否し、既存リスト、順序、進捗、リスト選択、現在対象およびマップ別現在地点を変更しない。匿名スロット、既定名、「1人目」「2人目」等を未入力名の代替として登録しない。[REQ-T-001][REQ-D-001][REQ-D-002]

手動入力のバージョン絞り込みは候補地点を狭めるためだけに使用する。候補を選択した時点で、その登録項目に対応するバージョン、正規マップおよび宝箱地点が確定し、巡回全体のバージョンは変更しない。候補地点の選択が成功した登録または更新は同じ巡回リストへ反映され、登録入口を閉じて主表示へ戻る。[REQ-T-002][REQ-T-004][REQ-D-005]

メンバー名は、前後空白を除き Unicode NFC に正規化した文字列を同一性判定に用いる。大文字・小文字、全角・半角、別表記および別名を推測変換しない。正規化後の名前が既存メンバーと一致する場合は新しい対象を増やさず、そのメンバーの現在 Treasure を更新する。一致しない新しい名前で既に 8 件ある場合は登録を拒否する。表示名は正規化後の非空文字列とし、既存対象の表示名は同一性が一致する更新で不用意に置き換えない。[REQ-T-001][REQ-T-006][REQ-D-005]

### 4.2 パーティチャット一括入力

一括入力は改行区切りの行を受け取り、各行から次の並びを認識する。

```text
(★プレイヤー名) マップ名 (X, Y)
```

- 行頭の時刻その他の文字、および座標後の文字は許容する。
- 括弧は半角 `()` または全角 `（）`、座標区切りは半角 `,` または全角 `，` を受理する。
- X/Y は 0 以上の整数または小数表記を受理し、前後の空白を無視する。
- 開き括弧直後の指定記号は `★☆●▲◆♥♠♣◇♦♡○□△▽` のいずれか一文字とし、省略も許容する。指定記号がある場合だけ名前から除外し、指定記号以外の先頭文字を暗黙に除去しない。記号を除いた名前を前後空白除去・Unicode NFC 正規化した結果が空なら、その行は名前不在として拒否する。
- マップは正式名または短縮名の完全一致を優先し、一意に特定できる部分一致を受理する。同じ正規マップ識別子が複数バージョンに現れる場合は一つのマップ候補として扱い、バージョンの違いは次の地点候補解決で判定する。異なる正規マップが複数一致する場合は、その行を曖昧として解決待ちにする。
- 座標は、候補となる全バージョンの正規マップ上の宝箱地点を対象に、X/Y 二次元距離が 1.0 以内の集合を調べる。該当がない場合だけ 2.0 以内の集合を調べる。異なる `(バージョン, マップ, 地点)` が一つだけなら、そのバージョンと地点を自動解決する。同じバージョン内の同一点を重複して表す master record は一意解決とみなさず、重複診断とする。
- 複数のバージョンまたは地点が残る場合は曖昧行として自動登録せず、候補のバージョン（利用者向け `3.x`〜`7.x` 表記）、マップ、地点および座標を利用者が選べる解決待ちにする。候補がない場合は範囲外・未知地点として解決不能にする。

一行から上記の並びを複数通り抽出できる場合は曖昧としてその行を拒否し、一部だけを推測採用しない。

空行は入力対象から除外する。構文不一致、空の名前、未知・曖昧なマップ、座標が数値でない、範囲外、候補がない、重複または参照不能な行は、行番号または入力順と理由を示す解決不能／解決待ち行として表示する。利用者は曖昧行について候補を一つ選び、構文・未知マップ・範囲外座標については入力を修正して再解析できる。利用者が選択または修正しない行は登録候補に含めない。入力全体に対する事前のバージョン選択は提供しない。[REQ-T-005][REQ-D-001][REQ-D-002][REQ-D-006]

解決済み行（自動解決された行または利用者が候補を選択した行）だけを、利用者の「登録」操作で適用する。解決不能／解決待ち行を残したまま、解決済み行だけを部分適用できる。解決済み行が一つもない場合は既存リストを変更しない。部分適用であっても、未適用行とその理由を入力画面に残す。[REQ-T-005][REQ-D-006]

同一性の比較は手動登録と同じ正規化済みメンバー名で行う。入力内で同じ名前・同じバージョン・同じ地点が複数回現れた場合は、入力順の最初の一行へ統合し、重複行を適用しない。同じ名前に異なる地点が現れた場合はメンバー競合として解決待ちにし、利用者が一つの行を採用するまでその名前の行を適用しない。既存リスト上のメンバーを含む行は更新、新しいメンバーの行は追加として扱う。[REQ-T-006][REQ-D-005][REQ-D-006]

新しいメンバーの追加数が空き（`8 - 現在の登録メンバー数`）を超える場合、入力順で空きに入る新規メンバーだけを追加候補とし、残りの新規メンバーを上限超過として未適用にする。既存メンバーの更新は空き数を消費しない。上限超過行を含む場合も、適用対象の更新・追加は一つの登録操作として行う。[REQ-T-001][REQ-T-006]

一括登録は、検証・同一性解決・競合解消・上限判定を終えた提案全体を一つの外部操作として扱う。保存に失敗した場合、追加・更新、順序、完了状態、リスト選択、現在対象およびマップ別現在地点のいずれも適用せず、入力の解決結果を保持して再試行できる状態にする。保存成功後だけ、手動順序では新規メンバーを末尾へ追加し既存対象の相対順序を維持し、自動順序では保存中のマップ別現在地点から残りを再計算する。[REQ-T-003][REQ-L-006]

### 4.3 表示と対象変更

Treasure は各登録項目について、正規化済みメンバー名、利用者向けバージョン、正規マップ、宝箱地点、未完了／完了、プレイリスト上の位置、リスト選択中か、現在対象であるかを別々に識別可能に表示する。利用者は、リスト選択、現在対象（地図・案内を前面表示し「次へ」の対象となるもの）およびマップ別現在地点（経路再計算の起点）を区別できる。登録済み対象と巡回リストの対象集合を分けない。完了対象は同じリストの元の進捗位置に表示し、未完了経路からだけ除外する。[REQ-T-002][REQ-D-003][REQ-D-005]

利用者がリスト項目を選択するとリスト選択だけを変更し、現在対象、地図・案内の前面表示、「次へ」の対象、完了、順序、マップ別現在地点および登録内容は変更しない。したがってリスト選択と現在対象は一致しない状態を許容する。リスト選択だけを変更する操作も保存対象であり、保存に成功した場合だけ新しいリスト選択を公開する。選択された項目を削除した場合はリスト選択だけを解除し、削除対象が現在対象でもあった場合に限り現在対象も解除する。削除されていない現在対象、保存済みマップ別現在地点および他の項目は巻き戻さない。[REQ-D-001][REQ-D-003][REQ-L-001][REQ-L-006]

手動順序中は、既存対象の地点変更で並び位置を維持し、新しいメンバーは末尾へ追加し、削除は該当対象だけを除いて残りの相対順序を保つ。自動順序中は、対象の追加・地点変更・削除・完了・取消が成功した後、保存済みマップ別現在地点から未完了の残りを再計算する。手動順序を自動へ戻すのは、利用者が「経路自動計算」を明示し、計算と保存が成功した場合だけである。[REQ-T-003][REQ-R-005][REQ-R-006][REQ-R-007]

Treasure の利用者向けバージョン表示は `Gxx` を使用せず、マイナーバージョンを `x` とした次の表記だけを用いる。

| legacy grade | 利用者向けバージョン |
| ------------ | -------------------- |
| G8           | 3.x                  |
| G10          | 4.x                  |
| G12          | 5.x                  |
| G14          | 6.x                  |
| G17          | 7.x                  |
| G18          | 7.x                  |

この分類は各登録項目の表示、手動入力の候補絞り込みおよび一括入力の候補解決に適用し、巡回リスト全体の選択値にはしない。内部 grade 数値、legacy JSON ファイル名および既存保存値は表示変更だけを理由に変更・破棄せず、同じ参照を持つ異なる系列の登録を一つのリストに混在できる。[REQ-T-004][REQ-Q-002]

#### 4.3.1 Treasure の現在対象と進行操作

新規 registration を含む登録操作が成功した後、`currentTarget` が未設定なら、更新後のプレイリスト順で最初の未完了 registration を `currentTarget` として設定し、その地図・案内を前面に表示する。未完了 registration がない場合は `currentTarget` を `null` のままにする。登録によって `listSelection` を設定または変更しない。すでに `currentTarget` がある場合は、新規登録によって別 registration へ切り替えず、その参照を維持する。したがって登録は、`listSelection` と `currentTarget` を同一にする操作ではない。[REQ-T-001][REQ-T-002][REQ-T-007][REQ-D-003]

同一メンバーの地点更新では registration identity、`listSelection` および `currentTarget` の既存参照を維持する。同じ地点の再登録は完了状態も維持し、別地点への更新は完了を解除する。地点更新後に `currentTarget` が未設定なら上記と同じ最初の未完了 registration の規則を適用し、設定済みなら更新対象を含めて既存 target を切り替えない。登録の保存に失敗した場合は、追加・更新、`listSelection`、`currentTarget`、地図・案内、順序、進捗および保存データを変更しない。[REQ-T-001][REQ-T-003][REQ-T-006][REQ-L-006]

Treasure の通常の巡回開始は、登録成功による上記の `currentTarget` 自動確立から「次へ」へ進む。独立した「再生」操作または control を、巡回開始のために利用者へ提供することは必須としない。リスト項目の選択だけでは `currentTarget`、地図・案内の前面表示、完了、順序またはマップ別現在地点を変更しない。現在対象がない状態での「次へ」、完了済みの現在対象での「次へ」、および空リストでの「次へ」は、従来どおり状態を変更しない。[REQ-T-002][REQ-T-007][REQ-P-001][REQ-P-002]

未完了の現在対象で「次へ」を実行すると、次を一操作で行う。現在対象を完了表示にし、元のプレイリスト位置に残し、その対象の地点を該当マップの現在地点として記録する。次の未完了対象は、現在対象の直後からプレイリスト順に一周して最初に見つかる未完了対象とし、それを現在対象にして地図・案内を前面に表示する。現在対象の後に未完了対象がなくても、前方に未完了対象が残っていればリスト先頭から続けて探索するため、完了済み項目を挟む手動・自動の混在配置でも同じ規則を適用する。自動順序では完了地点を起点に残りを再計算し、手動順序では残りの相対順序を維持する。ここで「最後の未完了対象」とは、操作前にリスト全体で未完了がその対象一件だけとなる状態を指す。現在対象が最後の未完了対象（単一項目、または他の全項目が完了済み）だった場合は、次の未完了対象を作らず現在対象を解除し、完了対象とマップ別現在地点を表示して全件完了とする。この最初の「次へ」は「戻る」で取り消せる。[REQ-T-007][REQ-P-001][REQ-R-005]

現在対象がない状態（直前の最終対象への「次へ」で全件完了となった状態を含む）での「次へ」、完了済みの現在対象での「次へ」、および空リストでの「次へ」は、完了、順序、マップ別現在地点、リスト選択および現在対象を変更しない。全件完了後の「次へ」は、新しい「戻る」対象を作らず、直前の最終対象を完了した「次へ」の「戻る」可能状態を消費・失効させない。したがって、最終対象を完了した最初の「次へ」の直後に「次へ」を押しても無操作のままであり、その後の「戻る」は最初の「次へ」を取り消す。これらの境界操作は「次へ」の取消対象にしない。[REQ-T-007][REQ-D-002]

直前の「次へ」が未完了対象を完了にした場合だけ、「戻る」を実行できる。戻るは直近の次へから順に、その対象を未完了へ戻し、対象の元のプレイリスト位置、操作前のマップ別現在地点および操作前の現在対象を復元する。自動進行で現在対象だけが変わった場合も、リスト選択は変更せず、戻るはリスト選択を変更しない。連続して戻る場合は一つずつ前の次へを同じ規則で取り消す。「次へ」未実行（リスト先頭で待機している状態を含む）、または既に完了済み対象への個別操作、登録変更、地点更新、削除、再生、リスト選択変更など別の状態変更が成功した後の「戻る」は無効で、何も変更しない。全件完了後に状態を変えない「次へ」はこの連続性を失効させない。任意の過去操作を選んで戻す一般履歴は提供しない。[REQ-T-007][REQ-P-002]

「完了」は現在対象に限らず各未完了対象から実行できる。対象を完了表示に残し、未完了経路から除外し、その地点をマップ別現在地点として保存する。個別完了では次へを暗黙に実行しない。リスト選択と現在対象の関係ごとの結果は次のとおりである。

- リスト選択と現在対象が同じ対象 A の場合、A を完了表示にした後もリスト選択と現在対象をともに A のまま保ち、A の地図・案内を前面表示する。
- リスト選択が B、現在対象が A で異なる場合、A の完了はリスト選択を B のまま、現在対象を完了済みの A のまま保ち、A の地図・案内を前面表示する。現在対象ではない B の完了はリスト選択を B のまま、現在対象を A のまま保ち、前面の地図・案内を変更しない。
- リスト選択または現在対象の一方だけがある場合、その参照をそのまま保ち、ない側を作らない。したがって、リスト選択だけの A を完了しても現在対象は `null` のまま、現在対象だけの A を完了してもリスト選択は `null` のままである。
- 両方が `null` の場合、対象を完了してもリスト選択および現在対象は `null` のままとし、対象の地図・案内を現在対象として表示しない。

いずれの場合も成功した完了は対象のマップ別現在地点を更新し、自動順序ではその保存済み地点を起点に未完了経路を再計算し、手動順序では他対象の相対順序を変えない。保存成功後だけ上記の完了表示、選択、現在対象、地図・案内、マップ別現在地点および経路を公開する。完了済み対象の「取消」は同じプレイリスト位置へ未完了として戻す。取消前のリスト選択と現在対象が同じ対象 A なら両方を A のまま保ち、異なる対象なら B と A をそれぞれのまま保つ。片方だけまたは両方が `null` の場合も、ない側を作らず既存参照だけを維持する。現在対象を取消した場合はその対象の地図・案内を前面表示し、現在対象ではない対象を取消した場合は前面の地図・案内を変更しない。手動順序では完了前の位置へ復元し、自動順序では取消前から保存されているマップ別現在地点を起点に残りを再計算する。個別の完了・取消は「戻る」の連続取消を失効させ、他の対象の完了や後続操作を巻き戻さない。完了・取消の保存に失敗した場合は、操作前のリスト選択、現在対象、地図・案内、完了、順序、マップ別現在地点および保存データを変更せず、失敗を表示する。[REQ-P-001][REQ-P-002][REQ-L-006]

対象削除および手動並べ替えは、リスト選択または現在対象を暗黙に別項目へ変更しない。選択対象を削除した場合はリスト選択を解除し、現在対象を削除した場合は現在対象を解除する。どちらの場合も別項目を自動選択・再生せず、最後に完了・探索したマップ別現在地点を巻き戻さない。地点更新・削除・並べ替えは「戻る」を失効させ、保存成功後だけ対象、順序、リスト選択、現在対象および進捗を表示へ反映する。[REQ-T-001][REQ-T-003][REQ-T-006][REQ-L-006]

### 4.4 地図のエーテライト案内表示

Treasure の通常の地図表示および宝箱地点を選択する地図表示では、表示対象マップに属するすべての有効なエーテライトを、継続的な案内表示として表示する。Mob Compass の地図表示および地点選択表示でも、表示対象マップに属するすべての有効なエーテライトを同じ規則で表示する。登録済み対象、未登録対象、完了状態および表示中の経路の有無によって、案内表示の対象を一部だけに絞らない。[REQ-F-006][REQ-A-003][REQ-A-004]

地図画像は背景だけを提供し、町名またはエーテライトのアイコンを案内表示の情報源として扱わない。対応中の G8、G10、G12、G14、G17 の各グレードに含まれるすべての地図画像は、画像自体に埋め込まれた町名・エーテライト表示を持たず、アプリの案内表示と同じ情報を重複して示さない。エーテライト情報は、同じ正規マップ識別子に対してグレードに依存しない共通の地図情報から解決する。[REQ-F-006][REQ-A-003]

有効なエーテライトごとに、アイコンのアンカーをそのレコードの実マップ X/Y に対応する位置へ固定し、町名をそのアイコンに対応するラベルとして表示する。地図の現在のズーム・移動を反映したアイコンのアンカー座標を `(x, y)`、表示可能な地図領域を左上 `(0, 0)`、幅 `W` CSS px、高さ `H` CSS px の矩形とする。アイコンの表示位置はラベル配置によって変更しない。

町名ラベルの表示矩形は軸に平行な CSS px の矩形とし、町名を Unicode NFC に正規化した後の Unicode code point 数を `n` として、幅を `8n + 16` CSS px、高さを 24 CSS px とする。表示文字列は当該エーテライトの日本語の町名だけとし、別の名称への翻訳・推測による置換はしない。町名全体をこの矩形内に収められない候補は配置可能とみなさず、文字列の一部を別の文字列へ置換・推測短縮せずにラベル全体を省略する。ラベル矩形は表示可能な地図領域からはみ出してはならない。ラベル矩形同士は、矩形の共通部分の面積が 0 より大きい場合に「重なり」と判定し、辺または頂点だけが接する場合は重なりとしない。

ラベルの配置候補は、アイコンのアンカーから 4 CSS px の間隔を空けた次の 8 方向に限る。候補順は `N`、`NE`、`E`、`SE`、`S`、`SW`、`W`、`NW` とする。ラベル矩形を幅 `w`、高さ `h` としたときの各候補の位置は次のとおりである。

| 候補 | ラベル矩形の位置                    |
| ---- | ----------------------------------- |
| `N`  | 下辺を `y - 4`、X 中央を `x` とする |
| `NE` | 左下角を `(x + 4, y - 4)` とする    |
| `E`  | 左辺を `x + 4`、Y 中央を `y` とする |
| `SE` | 左上角を `(x + 4, y + 4)` とする    |
| `S`  | 上辺を `y + 4`、X 中央を `x` とする |
| `SW` | 右上角を `(x - 4, y + 4)` とする    |
| `W`  | 右辺を `x - 4`、Y 中央を `y` とする |
| `NW` | 右下角を `(x - 4, y - 4)` とする    |

したがって、採用候補の矩形はすべてアイコンの近接範囲をこの 4 CSS px の配置単位で満たし、アイコンとラベルの対応を示すコネクタ線は表示しない。

アプリは、表示可能な地図領域内にあり、同時に表示する他の町名ラベルと重ならない候補だけを配置候補として扱う。配置候補の組み合わせは、各エーテライトにつき最大一候補、候補矩形同士に正の面積の重なりがないこと、表示ラベル数が最大 8 件以下であることを満たすものとする。表示ラベル数が最大となる組み合わせを第一順位で採用する。最大数の組み合わせが複数ある場合は、エーテライトの安定識別子を Unicode code point 昇順に並べ、各組み合わせについてその順の表示・非表示を `1`・`0` で表すベクトルを作り、最初に異なる要素で `1` となる組み合わせを優先する。表示するエーテライト集合が同じ場合は、同じ安定識別子順に候補順位 `N`、`NE`、`E`、`SE`、`S`、`SW`、`W`、`NW` を数値化したベクトルを比較し、最初に異なる要素の数値が小さい組み合わせを優先する。この規則で採用されなかった町名ラベル、または有効な候補が一つもない町名ラベルはラベル単位で省略・非表示とし、採用されなかった理由を別の町名へ置換することはしない。アイコンはラベルの採否にかかわらず全件を実座標へ表示する。[REQ-F-007]

通常の地図表示と地点選択表示は、同じ有効なエーテライト集合、同じマップ投影、同じ表示可能な地図領域 `(W, H)` に対して、上記の同じ配置・重なり・上限・省略・同率規則を適用する。狭いまたは過密な viewport では表示可能な地図領域が変わるため町名ラベルの採否が変わり得るが、同じ領域と入力であれば両表示は同じラベル集合と候補順位を返す。ラベルを省略・非表示にする場合も、アイコンの位置を町名表示の都合で移動しない。[REQ-F-007]

エーテライトのアイコンおよび町名ラベルは案内表示専用であり、クリックまたはタップの対象にしない。これらへのクリックまたはタップ、または案内表示の再描画は、地点の登録・選択・置換・削除、完了・取消、探索、順序、現在地点、保存状態その他の周回状態を変更しない。利用者がアプリ上でエーテライトの町名、座標その他のマスター情報を登録・編集する入口は提供しない。[REQ-F-008]

## 5. Mob Compass の登録

### 5.1 検索とフィルタ

登録画面は名前検索、拡張エリアフィルタ、種別・ランクフィルタおよび候補一覧を表示する。ソロでは一般モブから B モブまで、パーティでは A モブ以上だけを候補一覧に含める。[REQ-M-001][REQ-M-002]

名前検索は、入力の前後空白を除き Unicode NFC に正規化した文字列について、正式名または登録済み別名に対する部分一致で判定する。ラテン文字の大文字・小文字は区別せず、全角・半角や別文字を推測変換しない。空の検索文字列は名前による除外を行わない。

複数フィルタは AND 条件で組み合わせる。一つのフィルタ内で複数値を選べる場合は OR 条件とする。検索結果が一件でも、文字入力だけでは登録せず、利用者が一覧のモブを選択した時点で対象を確定する。該当なし、読み込み失敗および無効なフィルタ値を識別可能に表示し、既存登録を変更しない。[REQ-D-001][REQ-D-002]

### 5.2 ソロ登録

一般モブまたは B モブを一覧から選択すると、そのモブに対応する現在のマスター候補地点を全件、一つの候補集合として即時登録する。登録後も登録画面と現在の検索・フィルタ状態を維持する。[REQ-M-003][REQ-M-008]

同じモブを再選択した場合は別対象を追加しない。現在のマスターに新しい候補があれば候補集合へ追加し、同一候補の進捗は維持する。マスターから消えた既登録候補は推測置換せず、未確認として扱う。[REQ-A-002][REQ-D-002]

一般モブは、未完了候補集合から 6 章の同一マップ巡回全体が最短となる一地点だけを訪問地点にする。別候補は候補として保持するが訪問地点として並べない。B モブは全ての未探索候補地点を訪問地点にする。[REQ-M-004][REQ-M-005]

### 5.3 パーティ登録

パーティで A モブ以上を選択すると、Treasure の地点選択と同系統の地図ダイアログを開く。ダイアログは選択モブの出現マップと、そのモブに対応する有効なマスター候補マーカーだけを表示する。利用者が一地点をクリックまたはタップすると、その地点を報告地点として即時登録し、ダイアログを閉じて登録画面へ戻る。[REQ-M-006][REQ-M-008]

ダイアログを閉じただけの場合、選択前の登録状態を変更しない。地図の任意位置、X/Y の自由入力、Z 入力および他のモブの候補地点は登録できない。

登録済みモブは候補一覧から再選択できる。別候補を選択した場合は旧地点を新地点で置き換え、対象を増やさない。手動順序では並び位置と完了状態を維持する。同じ地点の再選択は重複追加せず、登録済みであることを示す。[REQ-M-007]

### 5.4 登録対象の削除

登録済みモブは、ソロ／パーティの現在モードから対象単位で削除できる。一般モブと B モブでは、そのモブの候補集合、採用地点、候補別探索状態、未発見、完了表示および巡回順上の全訪問地点をまとめて除く。A モブ以上では、選択報告地点、完了表示および巡回順上の訪問地点を除く。削除を討伐または完了として扱わず、他のモブと他モードを変更しない。[REQ-D-001]

手動順序では削除対象だけを外して残りの相対順序を維持する。自動順序では保存済み現在地点から残りを再計算する。削除対象が現在地点と同じでも保存済み現在地点は巻き戻さない。削除後に同じモブを選択した場合は新規の未完了対象として登録する。削除自体の取消は提供しない。[REQ-R-005][REQ-R-006][REQ-R-008]

## 6. 自動経路

### 6.1 算出対象と不変条件

自動経路は、現在のアプリまたは Mob モードに属する未完了かつ有効な訪問地点だけを対象とする。完了、探索済み、未確認または参照不能な地点は経路から除外するが、進捗一覧から隠さない。[REQ-A-002][REQ-D-003]

ソロでは同じマップの一般モブ採用地点と B モブ未探索候補を一つの経路に統合する。パーティでは同じマップの全報告地点を統合する。Treasure では同じマップの未完了宝箱地点を統合する。[REQ-R-004]

### 6.2 マップ間の評価

自動経路候補は次の順で比較する。[REQ-R-001]

1. 隣接する訪問地点の正規マップが変わる回数を最小化する。初回地点へ到達する移動と巡回終了後の帰還は、この回数に含めない。
2. 遷移回数が同じ候補では、同一マップ内の X/Y 二次元距離の合計を比較する。テレポ料金およびロード時間は順序評価に使用しない。
3. 同一評価となる全体経路が複数残る場合は、同率候補があることを表示する。そのうえで、各経路の訪問地点を巡回順に並べた `(正規マップ識別子, X, Y, 対象の安定識別子)` の列を作り、文字列は Unicode code point 昇順、X/Y は数値昇順として列同士を辞書順比較し、先頭となる一経路を表示上の採用経路とする。この規則は新しい移動負荷の優先軸ではなく、同じ入力と状態に同じ表示順を返すためだけに用いる。

### 6.3 同一マップの評価

同じマップでは、X/Y の二次元直線距離の合計が最小となる開始地点、一般モブの採用地点および訪問順を一体として選ぶ。距離は `sqrt((X2-X1)^2 + (Y2-Y1)^2)` とし、経路内の連続区間を合計する。終了地点からの帰還距離は含めない。[REQ-R-002][REQ-M-004]

そのマップに保存済み現在地点がある場合は現在地点を開始地点とする。ない場合は有効なエーテライトを開始候補とし、全訪問地点を巡る合計距離が最小のものを選ぶ。[REQ-R-003][REQ-R-005]

同じ最小距離となる経路が複数ある場合は同率であることを表示し、正規マップ識別子と対象の安定識別子は Unicode code point 昇順、X/Y は数値昇順として順に比較し、一つの表示順を決める。この最終規則は新しい移動評価軸として扱わず、同じ入力と状態には同じ表示順を返す。

### 6.4 再計算と計算不能

自動順序では、次の成功した状態変更後に、変更後の未完了集合で残りの経路を再計算する。[REQ-R-005][REQ-R-006]

- 対象の追加、地点の置換または削除。
- 完了または完了取消。
- B モブの「次の地点へ」、その取消または「探索をやり直す」。

完了または探索した地点を、そのマップの現在地点として保存する。以後の同一マップ再計算はその地点から開始する。別マップの保存済み現在地点は変更しない。

有効なエーテライトがない、訪問地点を解決できない、必要な補助情報が不足するなど経路を成立させられない場合は、理由と対象を識別可能に表示する。失敗した自動計算で既存順序、手動・自動区分、現在地点または進捗を変更しない。

未完了の訪問地点が一件もない場合は、経路が空であることを正常な結果として表示する。「経路自動計算」を実行した場合は空の自動順序として保存でき、計算不能エラーにはしない。

## 7. 手動順序

### 7.1 手動への切替と自動への復帰

利用者が訪問地点を並べ替えた時点で手動順序に切り替え、画面に「手動」であることを表示する。手動順序は、利用者が「経路自動計算」を実行し、計算と保存の両方が成功した場合だけ「自動」へ戻る。[REQ-R-006]

手動順序中は、登録、地点変更、削除、完了、取消またはマスター更新を理由に既存訪問地点を自動で入れ替えない。

手動順序中に複数候補を持つ一般モブを追加する場合は、既存訪問地点の順序を固定したまま末尾に一地点を追加する。末尾の既存地点が同じマップならその地点からの距離が最小となる候補を採用する。末尾が異なるマップまたは既存順序が空なら、対象マップの有効な各エーテライトと各候補の組み合わせから距離が最小となる組み合わせを選び、その候補を採用する。同率時は文字列を Unicode code point 昇順、X/Y を数値昇順とする `(正規マップ識別子, X, Y, 候補の安定識別子)` の順で先頭を採用する。採用地点は、当該モブの削除・再登録または明示的な経路自動計算まで、他対象の追加・変更・完了を理由に自動変更しない。[REQ-M-004][REQ-R-006][REQ-R-007]

### 7.2 追加、変更および削除

Treasure の新規対象、ソロの新規一般モブ採用地点およびパーティの新規対象は既存順序の末尾へ追加する。地点変更は同じ並び位置を維持し、削除は該当地点だけを除く。[REQ-T-003][REQ-R-007]

新規 B モブは候補地点を個別の訪問地点として扱い、既存順序の末尾地点から全候補を巡る追加距離が最小となる順で、まとまって末尾へ追加する。末尾地点が別マップまたは既存順序が空なら、その B モブのマップで 6.3 により選ぶエーテライトを起点に同じ規則で並べる。同率時は 6.3 の安定順を用いる。[REQ-R-007][REQ-R-008]

B モブの各候補地点は一般モブ等の訪問地点と同じ単位で任意位置へ並べ替えられる。並べ替え後に同じ B モブの地点が連続している必要はない。[REQ-R-008]

### 7.3 進行中の順序

手動順序で対象を完了した場合は、その対象の訪問地点だけを未完了経路から外し、残りの相対順序を維持する。取消時は完了前に占めていた位置へ戻す。他の対象に対する後続操作は巻き戻さない。[REQ-P-002]

B モブの「次の地点へ」では現在候補だけを外し、残りの相対順序を維持する。取消時は操作直前の位置と順序を復元する。

## 8. 進行、完了および取消

### 8.1 完了

Treasure の宝箱対象、一般モブ、B モブおよび A モブ以上は、それぞれ対象単位で「完了」を実行できる。完了対象は進捗一覧の元の位置に完了表示で残し、その対象に属する全訪問地点を未完了経路から除外する。アプリは候補地点への到着、時間経過またはゲーム状態から完了を自動判定しない。[REQ-P-001][REQ-S-002]

一般モブは討伐数を保持・表示せず、「次の地点へ」を提供しない。B モブの完了時は、完了直前の候補地点別の未探索・探索済み状態を取消用に保持する。

### 8.2 完了取消

各完了対象に「取消」を表示する。取消すると当該対象だけを未完了へ戻す。手動順序では完了前の位置へ戻し、自動順序では保存済み現在地点から残りを再計算する。取消対象以外の完了、探索、登録、順序および現在地点は巻き戻さない。[REQ-P-002]

B モブでは完了直前の各候補の探索状態も復元する。完了後に生じたマスター変更で復元対象を解決できない場合は推測置換せず未確認として表示する。

### 8.3 B モブの探索

B モブの現在候補地点には「次の地点へ」を表示する。実行すると、その地点を探索済みにし、その地点を現在地点として保存し、残りの未探索候補を現在地点から進む経路へ更新する。一般モブとパーティ対象にはこの操作を表示しない。[REQ-P-003]

直前に成功した状態変更操作が「次の地点へ」である場合だけ、「次の地点を取り消す」を一回実行できる。取消により、その一操作で変更した候補状態、順序および現在地点を操作直前へ戻す。別の状態変更操作または取消を行うと、この取消権は失効する。過去の任意地点は選択して戻せない。[REQ-P-004]

全候補が探索済みになると対象を「未発見」と表示し、完了にはしない。「探索をやり直す」を実行すると全候補を未探索へ戻し、その時点の現在地点から再計算する。手動順序の場合は、候補を 7.2 の新規 B モブ追加と同じ規則で末尾へ追加する。時間経過、再読み込みまたは再訪だけでは再探索へ戻さない。[REQ-P-005]

## 9. 保存、復元および全消去

### 9.1 保存対象

状態変更操作が成功した時点で、その状態境界に必要な次を保存する。[REQ-L-001]

- Treasure: 登録項目ごとの正規化済みメンバー名、バージョン、正規マップおよび宝箱地点、完了状態、プレイリスト上の進捗位置、手動・自動区分、未完了の巡回順、リスト選択、現在対象、マップ別現在地点。リスト選択と現在対象はそれぞれ 0 件または 1 件の独立した対象参照として保存し、一方を他方の代用にしない。再生中／一時停止中を表す状態や、連続した「次へ」の戻る履歴は保存しない。
- Mob ソロ: 登録モブ、候補集合、一般モブ採用地点、B モブの候補別探索状態、完了・未発見、手動・自動区分、巡回順、マップ別現在地点、取消に必要な直前状態。
- Mob パーティ: 登録モブと選択報告地点、完了状態、手動・自動区分、巡回順、マップ別現在地点。
- Mob 共通: 最後に選択したモード。

Treasure の現行保存レコードの外部キー、世代、認識条件および旧保存の移行入力は 9.1.1 で定める。Mob の保存媒体・キー・内部形式および状態境界の分割方法は Design で定める。ただし、三つの状態境界を独立して復元・消去できなければならない。

#### 9.1.1 Treasure 保存レコードの世代と認識

混在バージョンの登録項目、リスト選択と現在対象の分離、プレイリスト位置およびマップ別現在地点を同時に保存するため、現行 Treasure レコードは旧レコードと外部から区別できる新世代を用いる。以下はこの仕様が認識する JSON 表現の正式な外部契約である。各 JSON object は記載した field だけを許可し、記載のない余分な field は root、`state`、配列要素、参照 object、旧形式の入れ子を含めて認識失敗とする。`integer` は有限の JSON number で整数、`finite number` は有限の JSON number、`non-empty string` は前後空白除去・Unicode NFC 正規化後に空でない文字列を表す。object の key 順序には意味を持たせない。

現行レコードは browser の同一 origin にある localStorage の `treasure-compass:treasure-session:v3` に保存し、値は次の exact field を持つ JSON object とする。

| object               | 必須 field と型・値域                                                                                                                                                                                                                                                                                                   | 任意 field |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| v3 root              | `schemaVersion`: integer の `3`、`sessionRevision`: integer `>= 1`、`masterIdentity`: `MasterIdentity` object、`state`: `V3State` object                                                                                                                                                                                | なし       |
| `MasterIdentity`     | `mapSchemaVersion`: integer `>= 1`、`mapDataRevision`: non-empty string、`appSchemaVersion`: integer `>= 1`、`appDataRevision`: non-empty string                                                                                                                                                                        | なし       |
| `V3State`            | `registrations`: `V3Registration` の 0〜8 件配列、`playlistOrder`: registrationId の配列、`orderMode`: `auto` または `manual`、`listSelection`: registrationId または `null`、`currentTarget`: registrationId または `null`、`mapCurrentLocations`: `MapCurrentLocation` 配列、`incompleteRoute`: `RouteReference` 配列 | なし       |
| `V3Registration`     | `registrationId`: non-empty string、`memberName`: 正規化済み non-empty string、`version`: `3.x`、`4.x`、`5.x`、`6.x` または `7.x`、`pointRef`: `TreasurePointRef` object、`completed`: boolean、`playlistPosition`: integer `0`〜`registrations.length - 1`                                                             | なし       |
| `TreasurePointRef`   | `gradeSetId`: non-empty string、`mapId`: non-empty string、`pointId`: non-empty string                                                                                                                                                                                                                                  | なし       |
| `MapCurrentLocation` | `mapId`: non-empty string、`pointRef`: `TreasurePointRef` object                                                                                                                                                                                                                                                        | なし       |
| `RouteReference`     | `registrationId`: non-empty string、`pointRef`: `TreasurePointRef` object                                                                                                                                                                                                                                               | なし       |

`playlistOrder` は `registrationId` の non-empty string を重複なく並べ、`registrations` の各 ID を一度ずつ含み、各 `playlistPosition` と同じ位置を示さなければならない。`listSelection` と `currentTarget` はそれぞれ `registrations` に存在する ID または `null` であり、互いの代用ではない。`mapCurrentLocations` は `mapId` を重複させず、各要素の `pointRef.mapId` がその要素の `mapId` と一致しなければならない。`incompleteRoute` は未完了登録を playlist の規則に従う順序で一度ずつ参照し、各 `RouteReference.registrationId` の `pointRef` は当該登録の `pointRef` と一致しなければならない。これらの配列が空であることは許容する。`TreasurePointRef` は表示上の系列だけでなく master 上の grade-set、map および point を一意に参照する形状であり、内部に legacy grade 相当の値を保持しても Gxx を利用者向け表示へ露出するためには使わない。v3 は mixed-version の各登録を個別に保持し、巡回全体の version field を持たない。再生中／一時停止中または「次へ」の取消履歴を v3 の保存 field に含めない。

同一の正規化済みメンバー名への地点更新では、その登録項目の `registrationId` を維持し、リスト選択および現在対象の参照を同じ登録へ結び付けたままにする。登録削除ではその参照を無効にし、新規メンバーには既存項目と衝突しない新しい登録参照を割り当てる。これらは保存された項目の同一性を表す外部意味であり、参照値の生成方法は定めない。master が `TreasurePointRef` または `MapCurrentLocation.pointRef` を解決できない場合でも、上記の object 形状と参照整合性を満たす限り構造的には有効とし、未解決理由を保持する。ただし正常な地点・経路・完了として採用せず、近似置換もしない。

現行 v3 を認識する条件は、指定 key と上記 exact root、`schemaVersion: 3`、全必須 field の型・値域・参照整合性・上限が一致することである。JSON 構文不正、root または入れ子 object の型不正、必須 field の欠落、enum／整数値域違反、非空名違反、重複登録参照・メンバー名・順序参照、8 件超過、`listSelection`／`currentTarget` の存在しない参照、または記載外 field は、その Treasure 保存境界全体を破損として拒否する。構造的に有効で master 参照だけが未解決の状態はこの拒否に含めず、上記の未解決診断として保持する。

旧 JSON の共通 field 形状も、認識対象を実際に存在する `treasure-compass:treasure-session:v2`、`treasure-compass:sessions:v1` および `treasure-compass:grade`／`treasure-compass:members` に限定して、次のとおり定める。`LegacyPoint` は exact field `{stableId?, pointNo, division, block, posX, posY, posZ, posT, time, pointName}` の object とし、`stableId` は任意の non-empty string、`pointNo` は integer、`division` は `P`、`T`、`R` または `Z`、`block` と `pointName` は string、5 個の位置・時間値は finite number とする。`LegacyMember` は exact field `{memberNo, memberName, mapNo, mapName, mapNameShort, mapPoint}` の object とし、`memberNo` は integer `0`〜`7`、`memberName` は string（移行時には正規化後 non-empty を要求）、`mapNo` は integer、`mapName` と `mapNameShort` は non-empty string、`mapPoint` は `LegacyPoint` とする。配列の空 slot は `null` とする。同じ slot の `memberNo` 重複は不正とし、legacy の `(grade, mapNo, pointNo)` は後述の lookup で解決する。

`LegacyRouteStep` は exact field `{orderNo, memberNo, mapNo, mapName, mapNameShort, memberName, point, teleportPoint?, isCompleted}` の object とする。`orderNo` は integer `> 0` かつ配列内で重複せず、`memberNo` は integer `0`〜`7`、`mapNo` は integer、`mapName`、`mapNameShort` および `memberName` は string、`point` は `LegacyPoint`、`teleportPoint` は省略または `LegacyPoint`、`isCompleted` は boolean とする。旧完全状態の `route` はこの要素の 0〜8 件配列、`isManualSort` は boolean、`activeStep` は integer `>= 0`、`bulkText` は string、`currentMapPoints` は string の map ID key から `LegacyPoint` への object（空 object を許容）とする。これらの入れ子 object にも記載外 field を許可しない。

`treasure-compass:treasure-session:v2` は現行 v3 へ変換するためにだけ認識する旧 key であり、v2 key の値の root は、現行実装で既存利用されている exact field `{schemaVersion, sessionRevision, state}`、または Design が保存 envelope として定めた exact field `{schemaVersion, sessionRevision, masterIdentity, state}` のいずれか一方とする。後者の `masterIdentity` は `MasterIdentity` と同じ exact object とし、両方を同時に許容する optional field にはしない。`schemaVersion` は integer の `1` または `2`、`sessionRevision` は integer `>= 1`、`state` は object でなければならない。`schemaVersion: 1` の `state` は exact field `{grade, members}`、`grade` は JSON number の `8`、`10`、`12`、`14`、`17` または `18`、`members` は `LegacyMember` の 8 件配列とする。`schemaVersion: 2` の `state` は exact field `{grade, members, route, isManualSort, activeStep, bulkText, currentMapPoints}` とし、前記の grade、8 件の members および `LegacyRouteStep` 等の型を必須とする。schemaVersion と state の field 集合が一致しない場合、型・値域・重複・順序参照が不正な場合、または上記二つ以外の root field がある場合は受理しない。

`treasure-compass:sessions:v1` は次順位の旧統合保存としてのみ認識する。値の root は exact field `{version, product?, treasure, mob?}`、`version` は integer の `1`、`product` は省略または string、`treasure` は必須の旧 `state` object、`mob` は省略または object とする。`mob` object の内部は Treasure の認識・移行対象外の opaque legacy value として検査もコピーもせず、root に記載外 field を許可しない。`treasure` は上記 `schemaVersion: 1` の state field `{grade, members}` と同じ exact shape だけを受理する。旧統合 key について Design と現行実装が実在を示すのはこの grade／members 部分だけであり、route 等を加えた別の統合形式は認識対象に推測追加しない。Treasure 部分の field、grade、members、入れ子形状が不正なら envelope 全体を拒否する。`product` や `mob` の状態を Treasure へ移行しない。

旧 separate 保存は、同一 origin の `treasure-compass:grade` と `treasure-compass:members` の二つの key の値を別々に JSON として読み、grade 値は JSON number の `8`、`10`、`12`、`14`、`17` または `18`、members 値は `LegacyMember` または `null` のちょうど 8 件の array とする。これらの値は object envelope を持たず、記載できる field はそれぞれ grade number と前記 LegacyMember の exact field に限る。地点のない `null` slot は空 slot として無視するが、地点がある occupied member の名前が空または既定名なら移行時に匿名登録として採用しない。一方だけが存在する、JSON 構文・型・値域・slot 重複・必須 field・入れ子形状が不正、または余分な field がある場合は、部分復元せず separate 境界全体を拒否する。

保存候補の認識優先順位は、(1) `treasure-compass:treasure-session:v3`、(2) `treasure-compass:treasure-session:v2`、(3) `treasure-compass:sessions:v1` の Treasure 部分、(4) `treasure-compass:grade` と `treasure-compass:members` の組、の順とする。上位候補が有効なら下位候補を読まず、複数候補を merge しない。上位候補の key が存在して不正な場合に下位候補を採用して破損を隠してはならない。いずれも存在しない場合だけ Treasure を未保存の初期状態として扱う。Mob の session、Mob preference、または別の試作保存をこの認識対象や移行対象に含めない。

### 9.2 復元と互換性

同じブラウザで再読み込みまたは再訪した場合、最後に正常保存された状態を復元し、保存済み現在地点から残りの巡回を継続できる。経過時間だけで消去、完了解除、探索状態の初期化またはエーテライト起点への変更をしない。[REQ-L-002]

復元時は Treasure の混在した各登録項目をそれぞれのバージョン・地点として扱い、巡回リスト全体へ一つのバージョンを適用しない。保存されたリスト選択が存在する登録参照なら、完了・未完了にかかわらずリスト選択として復元する。保存された現在対象が存在する登録参照なら、リスト選択とは別の現在対象として復元し、master 参照が解決できる場合はその地図・案内を前面に表示できる。master 参照だけが未解決の場合も現在対象の登録情報と未解決理由を保持するが、正常な地図・経路として表示しない。どちらか一方が `null` の場合に他方から補わず、選択がない場合に先頭未完了を現在対象にするのは利用者が「再生」を実行した時だけであり、再読み込みだけでは暗黙に再生しない。保存されたマップ別現在地点は、リスト選択および現在対象と別に経路起点として復元する。[REQ-T-004][REQ-T-007][REQ-L-001][REQ-L-002]

「戻る」に必要な連続した「次へ」の取消情報は再読み込み・再訪をまたいで復元しない。復元直後の「戻る」は無効であり、新しい「次へ」が成功した後だけ、その操作から連続して戻れる。[REQ-T-007][REQ-L-001][REQ-L-002]

9.1.1 の認識優先順位で選んだ旧 Treasure 保存は、初回だけ現行 v3 へ移行する。旧グレードは各登録の map／point 参照を解決するためだけに用い、利用者向けには `Gxx` を表示せず、G8 → 3.x、G10 → 4.x、G12 → 5.x、G14 → 6.x、G17 → 7.x、G18 → 7.x の対応を各登録へ適用する。旧保存に一つの選択グレードしかない場合も、それを新リスト全体の選択値や現在対象として復元しない。新たに必要となるプレイリスト順、完了、リスト選択、現在対象およびマップ別現在地点が旧保存に存在しない場合は、正規の非空メンバー名と解決できた地点を未完了の自動順序・リスト選択なし・現在対象なし・マップ別現在地点なしとして v3 に変換する。[REQ-Q-002][REQ-T-004][REQ-D-005]

旧 separate 保存の空スロット（地点もないもの）は登録対象へ変換せず無視する。地点があるのに空または既定名しかない旧登録は匿名の正常登録として採用せず、旧保存を変更せずにその Treasure 境界の移行失敗と診断を表示し、初期状態を開く。構文、root、型、必須構造、正規化後の非空名、同一性、重複または順序を検証できない旧データは推測補完せず、その Treasure 境界の移行を全体拒否する。legacy の `(grade, mapNo, pointNo)` が一つでも未知または曖昧で stable map／point へ一意に変換できない場合も、部分移行せず旧保存を保持する。これに対し、認識済み v3（またはその v3 への変換後）の登録・mapCurrentLocations の参照だけが現在 master で解決できない場合は、構造的に正しい未解決登録として情報と理由を保持し、正常な巡回対象・地点・完了として扱わず、経路から除外し、近い地点や同名地点へ置換しない。[REQ-D-002][REQ-Q-002]

旧保存を変更または消去するのは、変換後の混在バージョンを含む v3 Treasure 状態を正常に保存でき、現行状態として公開した後だけとする。変換または v3 の保存に失敗した場合は旧保存を保持し、v3 を公開せず、再読み込みで旧保存を再び移行できる状態を保つ。旧 key の削除・移行済み扱いに失敗しても、保存済み v3 を優先し、旧値を再移行して二重登録しない。Mob の旧試作状態を Treasure の正規状態へ移行しない。[REQ-Q-002][REQ-L-006]

これらの current／legacy key は、運用中 Treasure entry と同じ browser origin の storage からだけ到達できる。origin 内で path または entry が変わっても同じ key を読める限り移行対象とするが、異なる origin ではブラウザの保存境界が分かれるため旧保存を移行成功として扱わず、旧値を変更・消去しない。異なる origin へ公開する場合は、旧 key へ到達して非破壊移行できる別の承認済み外部移行契約を公開前に定めるまで、既存 Treasure 保存互換を主張しない。[REQ-F-001][REQ-Q-002]

保存データの構造、型、同一性または順序参照の一部が空、不正、不完全、未知で、状態全体の一貫性を確認できない場合は、その状態境界を部分復元しない。影響するアプリまたはモードだけで復元失敗を表示し、他の正常な境界は復元する。旧形式については、認識済みの構造でも legacy lookup が一つでも失敗すれば移行全体を拒否する。現行 v3 または v3 へ変換済みの構造的に正しい状態内で master 参照だけが解決不能な場合は、上記の未解決診断として保持する。元データを正常状態として上書きしない。

### 9.3 保存失敗

状態変更を保存できない場合、その操作は失敗として扱い、画面上の周回状態を操作前の最後に正常保存された状態へ保つ。Treasure では登録、解決済み一括入力の適用、選択・再生、完了・取消、次へ・戻る、並べ替え、自動計算の切替に伴う対象、順序、進捗、選択およびマップ別現在地点を部分適用しない。保存失敗を識別可能に表示し、再試行または入力修正が可能な状態にする。成功通知、完了表示、順序変更、モード変更または消去済み表示を行わない。[REQ-L-006]

保存失敗は、他の状態境界および最後に正常保存されたデータを変更しない。一括登録、全消去、自動計算への切替および取消を含む一操作の一部だけを適用しない。

### 9.4 全消去

Treasure の「全消去」は Treasure の登録、順序、進捗および現在地点だけを対象にする。Mob の「全消去」は現在表示中のソロまたはパーティだけを対象にする。[REQ-L-003][REQ-L-004]

実行前に、確認画面の見出しと本文で「Treasure Compass」「Mob Compass ソロ」「Mob Compass パーティ」のいずれを消去するか示す。利用者が確認した場合だけ保存済み状態を初期化し、キャンセル時は何も変更しない。保存に失敗した場合も何も変更しない。[REQ-L-005][REQ-L-006]

## 10. マスターデータと入力異常

### 10.1 必須の意味情報

利用者向け機能が参照するマスターは、少なくとも次を一意に対応付ける。[REQ-A-001][REQ-S-005]

- 地図の安定識別子、正式名、表示名、地図画像、および X/Y それぞれの包含下限・包含上限で表す有効範囲。地図画像は背景として扱い、対応中の地図画像に町名またはエーテライトのアイコンを埋め込まない。
- エーテライトの安定識別子、所属マップ、`division`、X/Y、町名。共通地図情報へ採用できるのは、所属マップの参照が解決し、検証済みで、`division=T` であり、X/Y が有限かつ所属マップの有効範囲内にあるレコードだけとする。`division=R` のレコードは、条件を満たしていても採用しない。テレポ料金およびロード時間はTreasureの経路評価へ使用しない。
- 対象の安定識別子、正式名、0 件以上の別名、拡張エリア、種別・ランクおよび出現マップ。
- 候補地点の安定識別子、対象、所属マップ、および 0 以上の有限数で所属マップの有効範囲内にある X/Y。
- 情報の出典、確認・更新に必要な情報および画像の利用条件。

同じ正規マップ識別子が複数グレードで使用される場合、エーテライトの安定識別子、実マップ X/Y、町名および案内表示に必要な情報は一つの共通地図情報として解決し、グレードごとの別レコードを別のエーテライトとして扱わない。エーテライトの視覚資産を再利用する場合は、公開前に出典および利用条件を確認する。ラベルは地図画像から切り出した町名を再利用せず、アプリの新しいラベルデザインで表示する。[REQ-A-003][REQ-A-004][REQ-S-005]

一般モブから B モブまでと A モブ以上をモード別に分類できないマスターは、該当対象を登録候補にしない。候補地点がない対象は選択不能とし、理由を表示する。

巡回対象が存在する各マップには、有効範囲内の X/Y を持つ有効なエーテライトを一つ以上必要とする。この条件を満たさないマップの対象は登録候補にせず、マスター不備として理由を表示する。

### 10.2 検証と更新時の外部結果

空、不正、不完全、重複、範囲外、参照先不明または相互に矛盾するマスター情報を正常な対象・地点・経路として採用しない。利用可能な他の対象まで全て隠す必要はないが、除外した情報と理由を利用者が識別できなければならない。[REQ-D-002]

エーテライト情報については、`division=T` でない、検証済みでない、所属マップを解決できない、町名がない、X/Y が有限でない、または所属マップの有効範囲外であるレコードを、エーテライト案内表示、エーテライト参照および経路計算へ採用しない。`division=R` は、検証済みで参照可能な場合も同じ範囲から除外する。除外したレコードは有効なエーテライトの件数へ含めず、別の有効なレコードの表示を妨げない。対象マップに有効なエーテライトが一件もない場合は、既存の「有効なエーテライトがない」マスター不備・経路計算不能の外部結果を適用し、無効レコードを代替起点として推測採用しない。[REQ-A-004][REQ-D-002]

有効なエーテライト集合に重複する安定識別子が含まれる場合は、その重複情報を有効なエーテライトとして採用せず、該当する案内表示・参照・経路計算を除外する。町名ラベルの配置は 4.4 の CSS px 矩形、8方向候補、最大 8 件および安定識別子順の決定規則を用い、通常の地図表示と地点選択表示でこの規則を変えない。[REQ-F-007][REQ-D-002]

利用者入力、マスター上の名称および復元できなかった値を表示する場合は文字列データとして扱い、HTML、スクリプトまたは命令として解釈しない。

マスター更新後も安定識別子で既存対象・地点を解決できる場合は、登録、完了および探索状態を維持し、現在の名称・分類・座標を表示する。解決できない場合は該当情報を未確認として保持し、完了または発見を推測せず、経路から除外する。利用者が削除、再選択または全消去するまで、別の対象・地点へ自動置換しない。[REQ-A-002]

### 10.3 名称とローカライズ

初期リリースで利用者に見えるマップ名、町名、対象名、既存 Treasure のチャット一括登録に用いるマップ名・町名および UI は日本語とする。初期リリースでは言語選択、英語等の翻訳、多言語 UI、または Mob の正式名・別名・検索語を別言語と照合する機能を提供しない。既存の日本語による Treasure のマップ名・町名の照合とチャット一括登録は、4.2 の入力契約を維持する。[REQ-D-004][REQ-T-001][REQ-Q-002]

将来の言語追加を行う場合も、マップ、エーテライト、対象その他の名称は安定識別子に対応する言語別の表示名として扱える外部意味境界を維持する。言語別名称が未提供または解決不能な場合に、別言語の名称を翻訳・推測して表示または検索結果へ採用しない。具体的な言語コード、翻訳データの形式および言語選択 UI は本仕様の v1 契約に含めない。[REQ-D-004]

## 11. スマートフォン表示

幅 320 CSS px 以上のスマートフォン viewport を対象とし、縦向きでは横方向のページスクロールを主要操作の前提にせず、次を完了できるようにする。[REQ-Q-001]

- Treasure の手動・一括登録、地点選択、経路確認、並べ替え、完了・取消および全消去。
- Mob のソロ／パーティ切替、検索・フィルタ、対象登録、パーティ地点選択、経路確認、並べ替え、完了・取消、B モブ探索および全消去。

地図ダイアログの候補マーカーと主要操作はタップで利用でき、固定領域によって操作対象が恒常的に隠れない。横向きでも同じ主要操作を利用でき、向きの変更だけで未保存入力または周回状態を失わない。表示領域が狭い場合はパネルと地図を切り替えてよいが、現在のアプリ、Mob モードおよび操作対象を識別できなければならない。

## 13. 下流への引継ぎ

### 13.1 Design で決める事項

- 同一リポジトリ内で Treasure と Mob を別アプリとして構成するモノレポのパッケージ、依存方向、ビルド入口および共有地図基盤の境界。
- 具体的な URL 文字列、公開先および配備構成。ただし、Treasure entry は 9.2 の同一 browser origin 条件を満たし、異なるアドレスから直接利用できる外部結果と既存保存への到達結果を変更しない。
- 経路算出アルゴリズム、内部状態モデル、Mob の保存媒体・キー・形式、コンポーネント分割、データ読込および失敗境界。Treasure の現行 key、v3 と legacy の世代、9.1.1 の exact field／必須・任意・型・値域・参照形状／余分 field 拒否、旧 key の認識優先順位、同一 origin 条件および移行の外部結果は 9.1.1〜9.2 で固定する。
- Treasure の登録項目・プレイリスト・完了・リスト選択・現在対象・マップ別現在地点・手動／自動順序・連続した「次へ」の取消情報を内部で所有する構造、ならびにその整合性検証。保存・復元後に本仕様の混在バージョン、選択と現在対象の分離、進捗、順序、現在地点および失敗時の外部結果を変えないこと。
- Treasure 一括入力の parser、行診断、候補解決、メンバー同一性・重複・競合・上限判定、および一括 logical commit の内部実現。行単位の自動解決、利用者解決、部分適用、既存リスト統合、順序・進捗保持および保存失敗時の外部原子性を変えないこと。
- 旧 Treasure 保存の decoder、legacy lookup、移行 marker、旧形式の保持または無効化の内部方式。9.1.1〜9.2 の key／envelope 認識、legacy lookup の全体拒否境界、各登録のバージョン化、匿名登録の不採用、混在リスト復元、構造破損と未解決 master 参照の区別、および移行前データの非破壊境界を変えないこと。
- マスターデータの具体的なファイル形式、配置、版管理、更新・訂正・公開手順。ただし、共通地図情報の安定識別子による参照、`division=T` の採用、`division=R` の除外および本仕様の検証結果を変えないこと。
- 通常の地図表示と地点選択表示へ案内表示を重ねる内部責務、ラベル配置の実現方法、アイコン資産の具体的な配置および表示技術。ただし、本文の表示対象、実座標、非操作性、背景画像との非重複を変えないこと。

### 13.2 Implementation / Test で決める事項

具体的な UI 部品、ソース構成、ライブラリ、テストコード、fixture、CI、画像編集手段、具体的な画像ファイルおよび公開手順は本仕様で決めない。検証では、各適合条件に加え、Treasure の空・部分・不正入力、全角・半角、空名、匿名／既定名、曖昧なクロスバージョン候補、未知マップ、座標境界、同一メンバー重複・競合、既存メンバー更新、新規追加、最大 8 件と超過、解決済み行だけの部分適用、登録後のリスト復帰、リスト選択だけの変更、選択済み・完了済みの「再生」、選択と異なる現在対象の「次へ」、先頭・末尾・空・全件完了の「次へ」、最後の未完了を完了した直後の無操作「次へ」と「戻る」、連続した「戻る」、個別完了・取消との併存、手動／自動の順序、現在対象・選択対象の削除／地点更新、保存破損、master 未解決参照、保存失敗、v3 の保存・復元、v2／統合 v1／旧 separate 保存の各 exact field・余分 field・優先認識と移行成功・失敗、同一／異なる browser origin 条件およびスマートフォン縦横表示を扱う。Mob と map の既存条件に加え、複数エーテライト、検証済み T と legacy R の混在、参照不能・範囲外エーテライト、同率経路および計算不能も扱う。画像資産を採用する場合は出典・利用条件の確認結果を記録し、地図画像に埋め込み表示が残っていないことを確認する。

### 13.3 未決定事項

具体的な URL 文字列および配備先は未決定だが、同一 browser origin から既存 Treasure 保存へ到達できるという 9.2 の互換境界を満たす Design / release configuration の選択である。Treasure の parser 実装、内部 state / snapshot schema、保存媒体、v3 の意味フィールドを扱う内部形式、legacy decoder、旧 key の cleanup および UI component 分割は Design / Implementation の選択であるが、4.1–4.3.1、9.1.1–9.2 の外部結果を変えないことを前提とする。エーテライト町名ラベルの近接範囲、表示領域、重なり判定、配置候補、表示上限、省略対象および同率時の優先順位は既に 4.4 と 10.2 で確定しており、上流へ再委譲しない。
